# Roguelike - Design Doc

Это короткий рабочий дизайн-документ по проекту. Его цель - показать, что я понимаю, какую игру делаю, какие системы уже есть, что было добавлено в рамках моей ветки, как я оценивала задачи и как вела работу через Git.

## 1. Общее описание игры

`Roguelike` - небольшая 2D-игра на C++ и SFML с компонентной архитектурой.

Жанр: roguelike / dungeon crawler с процедурным лабиринтом, врагами, предметами и переходом между уровнями.

Цель игры: выжить в лабиринте, уничтожить всех врагов на уровне, собрать полезные предметы и перейти на следующий уровень. После зачистки уровня игра сохраняет состояние персонажа и запускает новый сгенерированный уровень.

Главный герой: игрок-воин, который может двигаться по лабиринту, стрелять снарядами, подбирать предметы, использовать зелья, экипировать броню и переносить прогресс между уровнями.

Враги:

- `Creeper` - быстрый враг с высоким уроном.
- `Warrior` - более крепкий и медленный враг ближнего боя.

Основной игровой цикл:

1. Игрок начинает в главном меню.
2. После старта генерируется лабиринт.
3. Игрок перемещается, стреляет, собирает предметы и сражается с врагами.
4. Когда все враги уничтожены, открывается переход на следующий уровень.
5. При смерти игрока показывается экран поражения и можно начать заново.

## 2. Механики и фичи

### Уже есть в игре

- Окно и игровой цикл на SFML.
- Компонентная архитектура: `GameObject`, `Component`, `TransformComponent`, renderer, collider, rigidbody.
- Процедурная генерация лабиринта.
- Полы и стены с вариантами текстур.
- Коллизии игрока со стенами.
- Система статистик: здоровье, броня, сила атаки.
- Ближняя атака врагов.
- Дальняя атака игрока снарядами.
- Столкновения снарядов с врагами и стенами.
- Враги с радиусом обнаружения игрока.
- Поиск пути врагов через `MazeNavigation`.
- Спавн врагов на безопасных позициях уровня.
- Спавн предметов.
- Звуки и фоновая музыка.
- Логирование.
- Тесты для `Vector` и `SaveSystem`.

### Что добавлялось в рамках направления UI / gameplay polish

Основная ветка разработки задания: `UI`. Перед защитой она была слита в `main` вместе с
остальными готовыми ветками.

Добавленные или существенно доработанные системы:

- HUD с отображением здоровья, брони, уровня и цели по врагам.
- Главное меню.
- Пауза.
- Экран победы на уровне.
- Экран смерти.
- Инвентарь с несколькими страницами.
- Панель описания предмета.
- Экипировка: броня, шлем, ботинки, оружейный слот.
- Hotbar для быстрых предметов на клавишах `1`-`6`.
- Popup-сообщения для обратной связи игроку.
- Перенос состояния между уровнями через `PlayerRunSnapshot` и `SaveSystem`.
- Event-driven обновление HUD через подписку на `StatsComponent`.
- UI-анимации: fade, slide, pulse, анимация огня на стартовом экране.
- Разделение UI на отдельные классы вместо одного большого файла.
- Исправления состояний UI: меню, пауза, инвентарь, game over и level complete не должны конфликтовать.
- Полировка стабильности: корректное уничтожение объектов, безопасный `SpriteColliderComponent`, единая инициализация random seed.
- Документация по UI и combat systems.

## 3. Оценка фич по сложности

Оценка примерная, в story points. Я использую шкалу:

- 1 SP - простая правка или маленькая фича.
- 2 SP - небольшая самостоятельная задача.
- 3 SP - средняя задача с несколькими файлами.
- 5 SP - сложная фича, затрагивает несколько систем.
- 8 SP - крупная фича с высоким риском интеграции.

| Фича / задача | Подзадачи | Оценка |
| --- | --- | ---: |
| Базовый HUD | Health/armor, счетчик уровня, цель по врагам | 3 SP |
| Event-driven HUD | Подписка на `StatsComponent`, отказ от постоянного polling здоровья | 3 SP |
| Главное меню и pause overlay | Экран старта, пауза, блокировка gameplay input | 5 SP |
| Game over и level complete screens | Состояния смерти, победы, restart/next level | 5 SP |
| Инвентарь | Слоты, страницы, выбор предметов, обновление из `InventoryComponent` | 8 SP |
| Equipment panel | Слоты экипировки, проверка типа предмета, замена предметов | 5 SP |
| Hotbar | Назначение предметов, клавиши `1`-`6`, синхронизация с инвентарем | 5 SP |
| Предметы и эффекты | Health/attack/speed potions, armor/speed/attack bonuses | 5 SP |
| Popup-сообщения | Сообщения, таймер жизни, fade/float animation | 2 SP |
| Run persistence | `PlayerRunSnapshot`, сохранение inventory/equipment/hotbar/stats между уровнями | 8 SP |
| UI-анимации и visual polish | Fade, slide, pulse, fire animation, death background transition | 5 SP |
| UI texture helpers | Общие функции отрисовки текстур, item icons, bars | 3 SP |
| Исправление UI state bugs | Приоритеты ввода, пауза, закрытие инвентаря, restart/next level | 5 SP |
| Документация UI/combat | README, `docs/ui-system.md`, `docs/combat-system.md` | 2 SP |
| Release/build polish | build scripts, runtime DLLs, cleanup generated logs | 3 SP |

| С помощью генеративных нейросетей и айпада сделала свои кастомные текстуры для большинства ассетов | 10 SP :((( |

Самые сложные части: инвентарь, hotbar/equipment интеграция и сохранение состояния между уровнями. Они затрагивают и UI, и gameplay, и данные игрока.

## 5. Работа с Git

### Основные ветки

- `main` - базовая ветка проекта.
- `UI` - основная ветка задания. В ней находятся все изменения, относящиеся к выбранному направлению UI и gameplay integration.
- `fix/release-packaging` - отдельная ветка для упаковки релизной сборки, build scripts, runtime DLLs и чистки generated artifacts.
- `chore/logging-improvements` - служебная ветка для улучшения логирования и снижения шума.
- `chore/remaining-polish` - служебная ветка для финального polish и архитектурной документации.

### Merge Requests / Pull Requests

Я разделяла работу так, чтобы каждое направление можно было проверять отдельно.

#### MR: `UI` -> `main`

Цель: основная функциональность задания.

Что внутри:

- UI-система.
- HUD.
- Inventory / equipment / hotbar.
- Popup messages.
- Main menu / pause / game over / level complete overlays.
- Run persistence между уровнями.
- UI-анимации.
- Интеграция UI с combat, stats и level objective.
- Исправления UI state bugs.
- Документация по UI и combat.

Почему отдельная ветка: это самая большая часть задания, ее удобно проверять целиком.

#### MR: `fix/release-packaging` -> `main` или `UI`

Цель: подготовка проекта к запуску на другой машине и чистота репозитория.

Что внутри:

- `build.bat`.
- `build-debug.bat`.
- `build-release.bat`.
- Копирование ресурсов и runtime DLL.
- Игнорирование `dist/`, build artifacts и runtime logs.
- Удаление tracked `Roguelike/Saved/Logs/log.txt`.

Почему отдельно: это не gameplay/UI-фича, а инфраструктура для сборки и сдачи.

#### MR: `chore/logging-improvements` -> `main`

Цель: улучшить качество логов.

Что внутри:

- Меньше лишнего debug spam.
- Более понятные сообщения для ошибок и важных событий.

#### MR: `chore/remaining-polish` -> `main`

Цель: финальная чистка архитектуры и документации.

Что внутри:

- Небольшие engine utility правки.
- Архитектурные пояснения.
- Финальный polish перед сдачей.

## 6. Текущее состояние проекта

Актуальная ветка для проверки и защиты: `main`. Все изменения по выбранному направлению
изначально разрабатывались в ветке `UI`, после проверки она была слита в `main`.

Проверки перед сдачей:

- `Debug|x64` - сборка успешна, 0 предупреждений.
- `Release|x64` - сборка успешна, 0 предупреждений.
- `EngineTest|Debug|x64` - 15 из 15 тестов прошли: 12 для `Vector2D` и 3 для
  `SaveSystem`.

Известные ограничения:

- Автоматические тесты покрывают не всю игру, а только часть engine/data logic.
- Для локального запуска тестов должен быть восстановлен x64-пакет GoogleTest.
- Проект рассчитан на Windows, Visual Studio 2022 и SFML 2.5.1.
